# 更新用PCの準備と名前漏れ防止

更新先は `kiwidori1122/kiwi-garakuta` です。以前のリポジトリのコピーを混ぜないでください。

## 最初の1回（PCごと）

1. Git for Windows、Python 3.12以上、GitHub CLIを用意します。
2. 新しい空のフォルダーへ取得します。

   ```sh
   git clone https://github.com/kiwidori1122/kiwi-garakuta.git
   cd kiwi-garakuta
   tools\setup-pc.bat
   ```

3. 専用のGitHubログインを求められたら `kiwidori1122` を使います。Gitの認証設定を全体に適用する質問には `n` と答えます。
4. 公開したくない語を画面の案内で登録します。一覧はPC内の `%USERPROFILE%\.kiwi-guard\deny.txt` にだけ保存されます。チャット・公開ファイル・コミットへ貼らないでください。
5. 最後の全履歴検査が通ったフォルダーをCodexまたはClaude Codeで開きます。

既存フォルダーの履歴や接続先が違う場合、セットアップは止まります。自動で移動・削除しません。作業ファイルを退避し、別の空フォルダーを使ってください。未コミットの作業がある場合も保存してから再実行します。

## 毎回の更新

- 同じ作業フォルダーを開きます。非公開の `AGENTS.md` と公開の `AI_RULES.md`、`CLAUDE.md` が共通の手順を指示します。
- 別のPCの更新を取り込むときは、作業を保存したうえで `git pull --ff-only` を使います。分岐したら無理に結合せず確認してください。
- 新しい作業クローンにも `sh tools/guard/setup-local.sh` を実行します。GitHub CLIは `sh tools/guard/gh.sh ...` 経由で使います。
- 作者・コミッターは `kiwidori <360543408+kiwidori1122@users.noreply.github.com>` に限定します。Gitの全体設定は変更しません。
- コミットとpushの際にフックが自動検査します。止まったら原因を非公開で調べ、内容を修正します。
- 配布用ZIP・EXEは既存のGitHub Actionsで作成します。手元のPCで作った配布物をそのまま公開しません。

## 検査するもの

| タイミング | 内容 |
|---|---|
| コミット前 | 作者・コミッターの名前とメールの組み合わせ、ステージ済みファイル名・全文 |
| メッセージ確定前 | コミットメッセージ |
| push前 | 送信するコミットの名義・メッセージ・変更ファイル全文、注釈付きタグの作成者 |
| GitHub Actions | 公開された変更の再検査と検査プログラムの試験 |

Unicodeのファイル名、全角・半角と大文字・小文字の違い、UTF-16テキストと埋め込み英数字文字列、ZIPの展開内容も確認します。検査不能なZIP、禁止語一覧なし、Pythonなしなどは検査を通しません。問題の語・パス・メールはエラーに表示しません。

禁止語は通常は部分一致です。先頭に `=` を付けると単語一致になります。例：`=taro` は単独の `Taro` に一致し、`Kintaro` には一致しません。上流ライセンスの別人名に反応した場合、著作権表示を削って通してはいけません。

## GitHub側の初期設定

リポジトリのActions secret `GUARD_DENY` に、各PCと同じ禁止語をカンマまたは改行区切りで設定します。一覧は秘密情報なので公開のVariablesには置きません。未設定なら検査は失敗します。GitHubのメール非公開設定も有効にしてください。

各PCの一覧とsecretは自動同期されません。語を追加したら両方を更新し、ほかのPCへは公開リポジトリ以外の安全な方法で反映します。

## 機械検査の限界

フックはGitのWeb画面編集などには適用されません。ActionsはGitHubへ届いた後の検知であり、一度も公開されないことを保証しません。通常の更新はセットアップ済みPCから行ってください。

禁止語にない情報、画像の中の文字、圧縮・暗号化された独自形式、外部のRelease説明・Issue・プロフィールなどは自動検査だけでは網羅できません。公開画像や説明文には個人情報を入れず、公開前の目視確認も続けてください。以前の公開履歴や第三者のコピーを消す仕組みではありません。
